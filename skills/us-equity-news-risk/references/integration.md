# Backend integration and acceptance

R32 production loads the two core files through the pinned backend loader. Installation alone would not prove integration; verify the active deployment and invocation receipt. The reference file itself is excluded from model input.

Load the UTF-8 bytes of `SOUL.md` and `SKILL.md` in both `data/news_event_model_v1.py` and `data/news_investment_model_v1.py`, through a shared bounded loader. Place them before the existing mode-specific prompt and public input. Keep the existing schema and deterministic validator authoritative. The integration reference need not enter the model prompt. Never ask the model to browse files to discover these instructions; the server must actually supply them.

Pin both file hashes in the deployment source closure. Include their hashes and exact instruction bytes in model cache identity and invocation receipt, alongside mode/version, schema hash, model, prompt, source bodies, background version and permitted position inputs. A changed skill must not reuse a success cached under old instructions. Missing, changed, oversized, or invalid UTF-8 instructions fail closed before model reservation; do not silently fall back. Set a combined core-file byte limit of 12 KiB. This bounds prompt input, not an asserted exact token count.

Preserve source-only identity-only input and account-aware minimal quantities. Do not add account secrets, full ledgers, or private unrelated holdings. Keep the existing Sol Medium configuration, shared rolling budget, single-flight lease, failure accounting and no automatic model retries. Instructions do not replace server guards or expand permission.

Minimum offline acceptance: both modes actually receive the exact pinned bytes; mutation changes cache identity and fails a stale deployment pin; missing files never invoke the model; schema remains unchanged; background-only evidence cannot become a trigger; KEEP/ABSTAIN and fractions retain original semantics. Use injected model transport for these tests. A later real call requires the parent task's explicit run authorization and existing budget.

Engineering evidence presently supports bounded discovery, source validation, conditional opinions and independently validated non-executable risk previews. Historical experiments are development cases with selection and model-memory risks. MRNA's contextual fixed-factor benefit cannot be attributed to the direct-action output, which paused buys without changing the account in that case. Cross-company KEEP and zero-benefit cases remain evidence, not exceptions to discard. No claim of preserved annual return, reduced full-cycle maximum drawdown, or reliable pre-crash detection is justified by this package.

Any subsequent economic validation must freeze source versions, publication assumptions, input context, model output and action mapping before outcome inspection; retain failures and zero differences; use identical initial accounts and real original risk state. Execute only after information and processing availability, charge actual configured costs, separate common pre-execution gaps, and report missed upside. Local event returns are not annualized or presented as a continuous strategy. No new experiment or automatic adoption is authorized here.

This supports document interpretation, not prediction or strategy-performance claims.
