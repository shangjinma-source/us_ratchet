# 历史普通股息接入合同

## 当前边界

`frontier_capped_next_open_research.py` 调用 `current_quantity_v2_next_open_book.run_next_open_book`。后者222—286行公司行动分支没有普通股息；未知持仓事件会阻塞。旧版声明普通股息排除。此次新增独立模块 `backtest/historical_dividend_ledger_research.py`，未修改冻结引擎、策略、生产账户，**未完成主账整合**。

已检查 `paper_dividend_journal_v1` 与 `data/paper_dividend_payment_v1`：它们依赖真实纸面账户的来源准入、支付审核与重放，明确不影响可用现金。本模块复用其分离权益和支付、幂等的原则；不伪造这些审核对象来调用现有接口。`conditional_gross_income_schedule` 仅为非再投资覆盖层，不能直接当作交易现金。

## 事件与时序

事件必须明确 `event_id/security_id/ex_date/payment_date/amount_per_share/withholding_rate/assumption/currency`。金额使用 Fraction；税率为显式研究假设，并不代表用户实际税务。支付日允许 null，不能从 WIKI ex-dividend 推导。当前研究版本不处理费用、支付修订、特殊除息/due-bill、负调整或实际券商到账。

1. 除息日交易前，以前一交易日结束持仓（明确 opening_quantity 接口）生成净应收。
2. 应收进入权益，但不进入可用现金。除息日卖出不失去应收；当天新买入没有对应权利。
3. 已知支付日到达后，可按明确研究时序支付，增加现金并等额冲回应收；非交易日支付在下一观察点反映，现金可用于哪个订单阶段必须由未来主账调用顺序明确。
4. 未知支付日永久保持应收，直到取得新证据并设计受审计的修订机制；本版本不会伪造或自行推迟支付日。
5. event_id 重试同输入返回原结果，不同输入拒绝；payment_id 重试同输入幂等；同权益换另一个支付ID仍拒绝重复支付。

## 下一轮主账接入要求

- 版本化引擎明确除息前取权、交易和支付先后；同日拆股/分红先核实每股单位，特殊派息另行处理。
- 将 receivable 加入权益而排除 sizing；仅把 paid_cash 的增量记入现金，不要每次重复加累计值。
- 使用原始价格时需检查普通股息全覆盖；使用含股息复权价不得再重复计息。
- 旧基线与新方案同时接入同一账法再比较，不能只给候选方案加股息。
- 当前模块仅验证会计状态转换，没有证明数据完整、真实支付、完整收益或策略优越。

验证命令：`D:\python\python.exe -m unittest discover -s tests -p test_historical_dividend_ledger_research.py`。覆盖期初持仓权利、除息日零持仓买入、事件冲突、提前支付拒绝、重复支付、支付权益守恒与未知支付日。

## 实际主账接口审计与接续方案

现有 `current_quantity_v2_next_open_book.run_next_open_book` 的现金、持仓、终止证券、订单去重集合与待交付权益均为函数局部状态。约151行调用 order_provider 时给出复制状态，返回值只采纳订单；不存在可注入现金的接口。约309行卖出和318行买入直接修改局部现金；约369行生成每日权益。由此可确认：仅包装 order_provider 不能正确完成股息再投资。

以下捷径不可作为主账整合：

- 逐日重新调用旧引擎会重置终止证券、订单ID集合和待交付合并/分拆权益；需要完整检查点协议才能安全使用。
- 给结果叠加股息权益不会让支付后的现金参与后续真实配置与买入，不能称为连续账户。
- 模拟出售虚构证券来注资会污染成交、费用与股票行情检查。
- 动态替换源代码或全局猴补丁会破坏来源绑定与可审计性。

最小正确接续是新增版本化内核入口，复用共享执行内核并显式接受 `cashflow_adapter`。这需要一次受控源码重构与冻结旧基线的等价回归，不能在“源码pins不改”条件下偷偷接入。当前没有复制整套引擎或宣称已实现。

建议接口阶段为：

1. `on_previous_close(state)` 给配置器真实已支付现金及单列应收，不提前暴露次日支付现金。
2. `before_open(day, opening_shares)` 处理当日除息取权；同日单位变化未审明则拒绝。
3. 旧内核正常执行冻结订单；默认支付在当日收盘阶段入账，因此不能资助当天开盘订单。
4. `after_execution(day)` 按已知支付日将应收转现金；非交易日到期款在下一交易日收盘阶段记入（明确保守研究假设，而非券商真实到账证明）。次日配置器可使用该现金。
5. 将现金增量纳入内核，权益含剩余净应收；成交与费用继续使用原执行器。新旧策略必须共用完全相同的时序。

需要的非空整合测试：持仓A在除息日卖出，同时买入B；股息应收不扩大当天B数量；支付日前无法买C；支付入账后下一次配置能增加C数量；原价除息跌幅与应收抵消；无股息输入的新旧引擎全部成交和权益逐项一致。此测试当前尚未运行，因为主账接口尚未实现。

数据缺失与工程限制分开：WIKI可以支持除息应计，未知支付日依然能贡献收益/回撤权益但不可买入；再投资路径需要额外支付日期证据，或在比较双方统一、明示的支付假设（不能静默当作真实到账）。这不是等待开盘才能解决的问题。

## 普通拆股独立复核扩展

独立复核器现在允许 `type=split`，要求执行actions与provider_actions完全一致，唯一证券/日期，交易会话内生效，正比例及非空来源引用（沿用旧review的证据形状检查，不代表引用外部真实性认证）。选择账户绑定在拆股前的前收盘单位检查；随后独立转换持仓与冻结订单数量、decision_mark，执行当日名义价交易。已有股息应收金额不因后续拆股翻倍。

零股不凭空折现金：持仓或订单转换非整数均拒绝；没有经过核实的cash-in-lieu金额/日期，所以此版本不宣称支持零股现金。与同证券股息同日仍拒绝；复杂身份、合并与分拆仍拒绝。

新增五项组合测试（15项review测试全部通过）：真实持仓拆股、冻结卖单由1股转2股、翌日除息前18股取权并买入2股、支付18现金后的权益128独立核对；错误比例/缺来源、同日股息、零股、订单数量篡改均拒绝。被审内核只生成测试输入账，复核器独立从声明订单/行情/行动计算预期，未调用内核产生expected。不运行经济搜索。
