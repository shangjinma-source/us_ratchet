# 新快照路径的成交与现金承接补验

2026-11-04。仅临时 SQLite 账户、合成行情与风险资料，不读取或写入真实账户，不运行 AI 模型，不下单。

新增 `tests/test_bound_snapshot_fill_cash_handoff.py`，复用原成交承接场景，接入正式 frontier 建议计算、观察日志、账户投影、绑定快照与 FastAPI preview 路由。目标展示字段按正式月目标视图补齐；网络连接及新增训练在场景执行期间禁止。测试中的成交/现金事件通过账户 store 写入，不冒充真实页面提交或券商成交。

四项场景通过：

- 全部卖出后，必须重新确认可用现金才恢复建议。
- 部分卖出保留剩余股数，重复成交事件保持幂等。
- 卖出后另用部分资金，只按重新确认的现金生成可负担买入。
- 可用现金不足一股及费用时，不生成买入；未成交卖出不能提前融资。

每次成功响应均验证展示账户与当前账本投影完全一致、账户版本与建议一致、月目标和提案绑定正确、观察日志保存成功；失败响应必须无订单、无报价、无可展示快照。连续刷新不改变账本、原目标或源风险库。

前端 `tests/bound_preview_snapshot_controller.cjs` 同次通过：现金增加/减少，保存成功但建议缺快照时拒绝显示，后续刷新不重复保存现金。此项为模拟传输测试。

新集成四项耗时约44秒。原成交承接四项另行回归。此前失败来自测试环境：Windows事件循环启动被禁网拦截，以及旧底层夹具缺少正式视图提供的提案字段；修正测试装配后通过，无生产代码修改，无需重启。

范围限制：这些结果补强新传输路径的工程证据，不替代盘中真实报价、用户真实现金提交、真实成交承接、AI分析完成或策略收益验收。
