# 跨页面目标恢复组件：已验证，未接入

关闭或重载页面会丢失现有控制器内存中的目标生成请求。此前“页面内刷新”补丁不能解决这一场景。本轮新增 `web/strategy_target_recovery_v1.js`，未修改已有生产脚本、active配置或账户。

## 组件已实现

- 发送生成请求前，将原事件编号、原因、账户版本和前一目标编号写入浏览器存储；不保存余额、持仓或成交。
- 同源Web Lock串行化读取、保存、原请求重放、结果核对和条件删除。缺少锁能力则拒绝生成。
- 新页面可恢复原请求；恢复入口没有待确认记录时不创建新操作。
- 网络错误、读取失败、异常成功响应、存储失败保留原操作，防止换新编号重试。
- 只有有效成功回执并完成状态核对，或明确未提交的结构化409响应，才清除对应原记录。
- 当前账户已变化时，允许确认原操作已完成并清除记录，调用方必须拒绝此次过期建议，随后按新状态刷新。

## 实际验证

`tests/strategy_target_recovery_v1_mock.cjs` 的13个场景通过，包含跨控制器恢复、双标签页恢复、账户版本变化、读取/写入/删除失败、错误回执、遗漏核对返回值、确定与不确定409、禁止覆盖其他待确认请求。

`tests/strategy_target_recovery_v1_browser.cjs` 使用真实Edge、localStorage和Web Locks；测试页面通过浏览器拦截提供，不连接生产服务。模拟响应丢失后重载页面，两个标签页同时恢复，验证原事件编号不变、模拟提交仅一次、记录最终清除。该测试使用模拟提交，不证明后端或真实账户已完成恢复。

独立agent审查完成；根据建议补充 `verify()` 必须返回布尔 `matches` 的检查，防止接线遗漏返回值时误清记录。
