余额分配只说明已有总现金属于哪家券商，合计必须与已确认的主账户现金一致；账户或转账版本变化后要求重新确认。资金预览也必须校验该分配。69 项 broker Python 测试、两项 Node 回归通过；真实预算计算已在隔离 HTTP 测试覆盖。正式页面仅作只读验收，未保存真实分账户余额、未转账或下单。

## 已实现

- 记录汇丰与盈立之间已转出、部分到账、全部到账，显示本金、在途资金、费用及本地发生时间。
- 独立 SQLite 日志，不发起银行转账，不修改策略账户现金、成交或委托。
- 保存响应丢失先查回；结果不明时沿用同一事件编号重试，避免重复记账。
- 在途资金不计入购买力。实际到账后，仍由用户确认最新购买力。

## 2026-11-14 现金衔接候选（未部署）

新增 `core/broker_transfer_cash_reconciliation.py`：按用户明确指定的转账事件与现金确认对应关系核对，不以金额相同自动归类。使用可信现金日志时间及转账版本；按估值时点恢复在途本金，后来到账不会倒改此前资产。手续费已在现金中扣除，不再次扣费；剩余差额继续保留待核对。47 项转账相关测试通过，其中新增 9 项覆盖转出、部分/全部到账、跨基准日在途、重复关联、缺失关联与时点/版本不一致。

此模块尚未连接正式现金/收益 API，不改变生产账户或购买力。接入前必须落实两券商各自余额的确认及汇总口径、关联记录持久化、转账后旧现金失效，以及转账/账户并发版本校验；不能把只有汇丰的余额当作双券商总现金。

### 分账户现金确认候选

`core/broker_cash_allocation.py` 保存现有总现金的券商归属，不建立第二本现金账。必须同时提供 HSBC/USMART 可用现金与冻结占款，分别求和匹配主账户；绑定账户与转账版本，任一变化则旧分配不可用于买单。SQLite 追加记录、重复请求幂等、冲突请求拒绝。61 项 broker 相关测试通过，其中余额分配新增 8 项。尚未挂正式路由；调用方必须在账户/转账快照锁内校验和写入，随后接现金保存与资金预览流程，不能仅凭独立存储测试宣称生产并发闭环完成。
