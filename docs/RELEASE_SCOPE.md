# 源码发布与清理边界

核对日期：2026-10-25。本文说明当前代码发布范围，不代表全部实盘验收已经完成。

## 本次应发布什么

- 当前工具与策略实际使用的 Python / JavaScript / PowerShell 源码、对应测试、依赖清单和简易使用说明。
- `data/` 根目录包含真正的 Python 模块，不能把该目录整体当缓存删除。`.gitignore` 只放行其根目录的 `.py` 文件。
- 每批以明确文件清单暂存，审阅差异后提交；不要使用 `git add .`，也不要为了凑齐发布而强制加入运行数据。
- 新增研究源码应有明确的复现入口、有限输入约定和验证证据。历史收益结果与当前生产策略的采用状态分别说明。

## 不进入普通源码提交的内容

真实账户数据库、成交或现金流水、浏览器状态、运行日志、行情缓存、回测大结果和本地服务 PID 均留在本机。`tmp/`、`outputs/`、`data/` 非源码内容已默认忽略。

`research_contracts/` 和 `config/strategy_server_active.json` 含当前部署清单、账户绑定及本机证据路径，默认不批量加入 Git。需要公开的独立研究设计可逐份检查后显式加入；可移植示例必须去除真实账户信息，不能直接复制当前生产清单。已经被 Git 跟踪的文件不因新增忽略规则而消失，仍需逐份审查。

## 克隆后的实际限制

当前生产入口为 `api.server`，`start_service.ps1` 默认使用本机 `D:\python\python.exe`，可通过 `-PythonPath` 改为其他解释器。源码检出不等于恢复当前真实账户：账户账本、已核验行情与公司行动证据、月度发布状态及任务配置均是独立的本地部署资料。

当前活动部署清单采用 v26，引用较早版本的配置与源码；这些引用还会进入 `research_contracts/`、`tmp/` 和 `data/` 中的本地证据。API 中也保留本地模拟账户描述符路径。普通源码发布不包含这些私人资料，因此不能宣称“新克隆即复现当前真实账户”或“已独立复现全部历史收益”。应保留清晰的缺失配置提示，后续通过脱敏示例与专门的初始化流程改善可移植性，不可把本地账本上传来绕过该问题。

## 如何确定源码清单

1. 从 `api/server.py`、当前 Windows 任务实际执行入口、已经采用的研究复现入口出发，沿本项目 `import` / `from` 引用收集依赖；同时检查动态导入、PowerShell 调用、HTML 静态资源、配置路径及 source pins。
2. 将依赖文件与 `git ls-files` 比较。2026-10-25 对服务和任务入口的静态初查得到 519 个 Python 依赖，其中 228 个尚未跟踪；这是候选集合，动态路径和配置校验仍需人工核对，不能把静态扫描当作运行完整性证明。
3. 新增文件只从 `api/`、`backtest/`、`core/`、`data/` 根部、`scripts/`、`tests/`、`web/` 选取 `.py`、`.js`、`.mjs`、`.cjs`、`.ps1` 和必要静态资源；另列 README、依赖和经审查的文档。配置、数据或生成文件不能因为在上述目录就自动放行。
4. 将已修改的跟踪文件单独复核，确认属于本次交付。检查新源码里是否硬编码私人账户值、认证内容或依赖未发布的输入；有固定输入的测试须明确标为需本地证据的集成测试。
5. 用该显式清单暂存；在提交前检查暂存内容、文件体积和源文件依赖。发布后验证远端目标提交，不以本地 commit 成功代替 push 成功。

## 什么可以清理

可以移除已被新简易说明替代的首页长篇操作说明，但有价值的研究说明应归档。合并且不再承担任务或发布入口的远端分支，可在确认提交已被保存后清理。删除远端分支不等于删除当前主分支中的源码。

本次远端分支清理候选为 `checkpoint/source-20261019`：仅在它的所有提交均已包含于发布后的 `main`、且远端提交核对一致后删除；不使用强制推送重写 `main`。本段记录操作边界，不冒充已完成的推送或删除结果。

源码必须同时证明：当前服务没有导入、任务没有执行、配置与 source pins 没有引用、保留的复现实验和测试没有依赖，才可列为废弃。仅凭 `v1`、日期旧或文件名含研究字样不能删除。当前 v26 仍引用早期版本链，不能直接删除早期模块。

除五项较新的策略任务外，检查时以下旧任务仍处于就绪状态，相关脚本不能视为废弃：

- `us_ratchet_golden_pit_snapshot`
- `us_ratchet_advice_snapshot_audit`
- `us_ratchet_ndx_challenger_forward_daily`
- `us_ratchet_ndx_dynamic_shadow_selection_daily_v3_reviewed_calendar`
- `us_ratchet_ndx_marginal_forward_daily`

两个旧版 dynamic shadow 任务已停用，但其源码仍可能被新版导入。清理须先查调用关系；不能借远端整理停止仍在使用的本地任务，也不能删除本地账户与历史证据。
