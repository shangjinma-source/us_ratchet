# 拆股运行时切换边界：现状与未来风险

当前没有证据证明生产UI与AI已引用不同账户或错配观察器。V30.attach_bound_snapshot将prepared.observed_daily传给BoundPreviewSnapshotV1；V32.attach_current_preview又以existing.observed构造请求层包装。news_investment_composition_v1绑定传入observed_daily.preview。UI增加包装不等于底层观察器已变化。

此前“UI和AI可能使用不同旧观察器”的表述限定为未来仅替换一条链路的迁移风险，不应当作现在线上故障结论。旧的完整链路继续服务现有账户；尚未支持拆股后的完整代次切换。

已定位的实际接口限制：V30要求账户服务严格为StrategyAccountService并检查账户数据库路径一致；旧服务、preview与evidence reader仍重放旧事件集合。拆股候选不能只替换store路径或UI路由，同时保留news对旧monthly/observer的闭包引用。

现有prepare_split_bundle、bound_split_sources、freeze_split_sources可以复用，但明确只准备与核一致性，没有生产激活或进程退役。完整实现须同时绑定账户投影、目标及proposal、风险epoch及reader、日执行provider、UI快照和新闻context/preview，旧异步任务必须因代次改变失效。数据库源写屏障不能跨网络/模型调用持有，失败恢复不得覆盖切换后的真实成交。

当前停止继续增加纯内容检查或独立包装模块。接下来只能以真实完整composition接线与一条临时账户闭环验收作为实施单元，并保留官方来源、历史单位坐标和真实券商可交易到账三个独立条件；合成夹具通过不授权真实账户激活。
