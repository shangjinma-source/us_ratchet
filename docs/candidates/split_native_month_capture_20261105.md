# Native new-month durable capture integration

`split_native_month_capture_20261105.py` supplies the native daily reader with actual outputs from the existing `capture_supplement` transport. The request retains a fixed session calendar, regular-hours restriction, at least 20 prior sessions, the earlier of risk epoch and 20-session lookback, full proposal/held/open-order/risk-peaks/exited domain, and the original four-field capture binding. Proposal identity and prior risk are separately bound. Capture slots remain immutable; an account/target/risk change during transport stops processing.

The original gzip transport and `split_frontier_supplement.review_generation` verify wire/body hashes, per-security receipt URL and time, requested intervals, source budget, source clock span, RSS future-notice scope, raw normalization and current session. Every original capture file is required unchanged in the final immutable archive. Different securities retain their own actual received times; the summary uses their maximum. The native daily reader was minimally extended to accept that verified per-security mapping and to return the actual risk projection for post-write snapshot verification.

A constructor-supplied `review_capture` remains an explicit server-owned independent source/basis admission boundary. Its result must bind the exact new capture bytes and timing; successful retrieval cannot itself certify adjusted versus as-traded prices. The callback's review time must fall between its real invocation and return and cannot precede receipt completion. No old capture is re-dated. Production wiring still needs an approved independent supplier-basis reviewer and source-pinned admission configuration. This module is usable capture-to-risk integration but is not that vendor certificate.

The source authorizer and HTTP payloads are explicitly controlled test fixtures, not live market or vendor-authenticity evidence. No production service, real account, model or economic backtest is touched.
