# 再入场候选：不完整证据误解除限制修复

2026-11-04，未挂载候选的源码审查发现：`review_reference_interval`正确返回`coverage_complete=False`，但`core.reentry_reference_v1.recover`只检查状态文字和区间字段，没有拒绝这一明确的不完整标记。旧跨层测试把该结果直接交给事务store，并断言恢复成功，实际覆盖了错误行为。

## 复现和改动

新增跨层反例先在旧代码失败：预期拒绝，但直接提交后限制被解除。修复后，恢复入口要求`coverage_complete is True`；缺失、False、整数1、字符串true均拒绝。该声明只是必要条件，不能代替上游来源认证。生产适配器仍不能把现有条件性资料改标为完整。

条件性资料直接进入store时，`REFERENCE_COMPLETE_COVERAGE_REQUIRED`使同一SQLite事务回滚，原风险状态和再入场状态均不变。正向合成测试现在显式增加测试专用封闭证券域声明并重新计算证据摘要，明确区别于真实资料审核，不将这种构造用于生产。
