# 服务切换前 HTTP 请求排空候选

当前启动脚本不能排空在途请求。新增独立 ASGI middleware 与进程内 RequestDrain：本地 supervisor 调用 begin 后拒绝新 HTTP 请求（503、no-store、retryable），已进入请求继续执行并在 finally 释放计数。wait 有明确超时，只有全部完成才返回 true；恢复需显式 resume，活动请求尚未完成时拒绝恢复。

2 项异步并发测试通过（0.080秒）：在途 POST 正常完成；新 POST/GET 被拒绝；未完成时不能恢复；显式恢复后可继续；异常也释放计数。不设置可由浏览器调用的控制端点，不取消已提交账户操作，不在 event loop 阻塞等待。

补充取消边界后共3项测试通过（0.019秒）：HTTP调用方取消时，实际application task由middleware强引用并shield，计数仅在该task终止回调中释放。测试在调用方已取消但模拟写任务未完成时确认wait(0)为false；写任务完成后才为true。该机制避免把客户端断开误认为写入结束，不保证进程被强制终止后的持久化；后台/其他进程边界仍如下。

尚未挂载8010。该 gate 只证明本进程 HTTP 请求排空，不能证明新闻后台、金融定时任务、其他进程已停止写入，也不能证明旧服务已经退出。正式切换仍需识别所有写入者、确认旧进程退出、重验最终账本并保护新成交后缀；不能凭 gate.wait(true) 恢复旧数据库或宣称完整切换完成。

启动脚本/active配置未改，生产服务和原任务保持运行。
