# AI复核请求等待上限候选

检查生产web/news_investment_review.js发现maxPolls只限制收到RUNNING之后的轮询次数，单次fetch或response.json没有等待上限。挂起请求会使busy保持，无法进入后续轮询退出分支。这是代码路径发现，不声称本次复现了用户网络环境的实际挂起。

完整未部署候选news_investment_review_timeout.js在mount内增加默认180000毫秒的单请求期限，覆盖fetch及JSON读取，使用AbortController并用Promise.race保证忽略abort的transport也能结束等待。dispose取消在途请求并清理定时器。沿用现有连接未确认提示；不自动重发POST、不宣称服务器任务被取消、不改变现金/成交或AI交易规则。此为单请求上限，不是整个模型任务保证三分钟完成。

验证：news_review_request_timeout.cjs覆盖fetch挂起、body挂起、轮询挂起、销毁、迟到返回及POST不重复；news_investment_review_mock、cached_evidence、现金/成交失效整组在候选上通过。旧mock用options是否存在判断POST，已改为检查method以兼容GET携带AbortSignal。首轮候选生成误把timeout局部变量插入两个渲染函数，回归发现后修正；测试曾等待挂起轮询导致Node无活动句柄退出，已改为先触发超时再等待，最终明确打印PASS。

news_investment_review_ready_uncertainty.cjs另行运行失败，其未使用候选环境开关且断言初始化网络请求为0，与生产已存在的事件状态读取不符；本轮不把它报成候选通过项，也未改该测试。

生产源码尚未替换、未重启8010。下一步需要按当前活动部署同步所有引用此静态脚本的pin配置、保存源码回退并验证页面实际使用新脚本；不能仅复制前端文件造成运行时源码校验失败。私有账户未修改。
