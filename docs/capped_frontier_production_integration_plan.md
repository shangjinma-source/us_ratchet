# 保存候选重排的生产接入边界

2026-10-25。候选已通过两个固定窗口的条件历史筛选，当前生产仍为 `MONTHLY_CAP50_EXIT20`。本页是工程接入清单，不是已经上线的功能清单；不新增回测或参数搜索。

## 已有实现如何复用

`core/saved_monthly_frontier_proposal.py` 从原生月目标的同次保存篮子构造独立提案，保留原目标、原选择和原三个内容ID。它复算50%裁剪后的训练分数，同分不替换；当前真实月目标98个保存篮子没有严格更优替代。

独立提案不能直接塞回原月目标的 `target_quantities`：`StrategyMonthlyTargetService` 及目标存储要求数量与原决策一致。修改原数量、重新签名而不保存提案依据，会失去原选择与实际执行之间的可追溯关系。

现有可复用接点如下，实际采用仍须独立配置和来源校验：

| 接点 | 已有能力 | 还需闭合的边界 |
|---|---|---|
| `MonthlyRuntimeRouter(runtime_builder=...)` | 将月度发布与保存目标的运行配置分开 | 新策略配置和提案须一起归档；本月原目标不能被新发布偷偷覆盖 |
| `StrategyMonthlyTargetService` | 明确初次、跨月及显式重新配置事件；校验账户版本和月份 | 在原目标之外保存提案ID；并发、重放及跨月过程中不能出现半套状态 |
| `plan_security_domain` / `aggregate_security_packets` | 原目标、实际持仓和未完成订单的完整数据域校验 | 新提案新增股票、已有退出锁定股票也须有完整证据；缺任何必要数据都等待 |
| `MonthlyPeakExitStore` | 保存收盘峰值、退出锁定、价格单位及月份状态 | 新股票补齐本月历史；旧股票退出锁定继续保留，不能因提案变化重置 |
| `DailyCompositionV7` / `DailyExecutionBridge` | 独立风险信号与原决策绑定，基于真实可用现金生成建议 | 信号、执行证据和结果都须包含同一提案ID；提案自身不授予执行权限 |
| 当前前端建议缓存和限仓目标展示 | 账户版本与原月目标绑定、失效时待核验 | 同一原目标的不同提案不能共用旧缓存；月目标列、有效目标列与K线应一致 |

## 最小端到端验收

1. 用隔离账户走正常新月选择，保存完整原目标及独立提案；证明同分沿用原方案、严格改善才替换，原输入费用0或1bp分别原样承接。
2. 原目标未选中的新股票必须通过身份、价格单位、公司行动、完整风险历史与当前报价检查；旧持仓、未完成订单和已退出股票不得从必要数据域消失。
3. 在同月重新读取提案或确认现金时，20%退出锁定不解除；新月正常选股成功且相应目标、提案已获准入后，才能按交易日历确定的决策边界重置，不能仅凭日历翻月解除旧锁定。已有风险库不得用空库替换。
4. 零现金、未成交卖款、报价过期、数据缺失、来源字节变化、账户/目标/提案版本变化均应拒绝或等待，不能退回未核验原数量继续下单。
5. 正常选择至建议生成、重复请求、并发账户变化、跨月切换和前端缓存失效均通过隔离全链检查，再形成可审阅发布与回退包。

以上通过后才能讨论启用；仅有纯提案或独立研究归档不等于生产全链接通。用户未要求改写当前已冻结的月目标，本轮也未改写。

## 证据和停止条件

工程验收只证明机制和状态衔接，不能把已经反复查看的历史窗口重新称为样本外。不得用新增更多回测替代上述接口缺口，也不为争取短期验收修改收益或回撤门槛。

实现中若发现缺少完整新证券证据、无法继承旧风险状态或无法隔离真实账户，应保留已完成的独立模块并明确缺口；不能用合成成功响应代替完整接入。
