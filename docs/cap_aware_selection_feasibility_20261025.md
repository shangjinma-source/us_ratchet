# 将现有50%约束放入选股排序：可行性审查

2026-10-25。仅审查现有实现和研究记录，未实现新选择器、未生成新候选、未启动回测。A的每日漂移治理已被双窗口条件筛选拒绝；本文件讨论的是月度选股目标与现行配置约束是否一致，不能与A组合后再解释成同一研究。

## 现行机制与数学差别

`backtest/continuous_guided_account_decision.py`先调用8192预算的V2，再加32步连续候选，并按未设单股上限的平均对数财富选出篮子。`backtest/continuous_guided_capped_account_decision.py`随后对胜出篮子逐股裁剪至净值50%，不重新排序、不把余量分配给其他股票。模块明确标记`cap_is_post_selection_overlay=True`，没有假称约束最优。这是设计取舍，不是已证实的代码错误。

一般而言，“先找不受50%限制的最好篮子再裁剪”不等于“在50%内找最好篮子”。一个只用于说明的无费用例子：现金100，A每期增长20%、B每期增长10%；未限仓训练目标选择全部A，裁剪后变成50的A和50现金，期末110；约束内50的A加50的B可到115。真实市场有亏损、相关性和有限样本，这个例子不预测实际收益。

现有31月度保存候选的裁剪后重新评分由主agent单独进行，属于零候选生成、零执行的诊断。如果保存候选中已有优于当前裁剪篮子的方案，可说明排序与部署约束之间确有实际差距；它仍不能证明替换后下一阶段收益更好。

## 已有研究是否重复

本次定向检索了当前选择器、cap封装、研究合同及`tmp`中的注册/决策/总结文件，未找到与当前“253日、12个21日情景、8192+32、单股50%、20%退出”完全同口径、已完成的约束内选股经济对照。

- `research_contracts/return_priority_uncapped_concentration_domain_20261014.json`明确让旧V2在不设分散限制的域内搜索；50%是后续独立配置覆盖层。
- `backtest/ndx_cap_frontier_analysis.py`审查的是旧NDX来源池/分数及权重实验，目标和搜索体系不同，不能当作当前版本已做。
- `backtest/quantity_ancestor_capped_resume.py`中的cap指训练目标上界证明的继承截断，和股票50%权重无关。
- 已完成的月度cap50、退出、两个月、动态再买入及A每日漂移实验，均不等于把cap加入候选排名。

这是对相关现有文件的排重结论，不是声称仓库中所有旧实验都已被穷尽证明不存在。

## 可复用接口与最低必要改动

不改生产或原冻结选择器，另写独立研究实现。资金与证据校验复用`data.current_research_capital_decision.decide_quantity_for_account(search=...)`；月度provider已有`decide`注入接口；原下一开盘kernel、20%退出、费用和公司行动处理继续复用。

独立V2需在候选生成和精确评分中统一使用 `q_i <= floor(E / (2*p_i))`，其中E为该分支决策收盘的可交易净值，p为同单位收盘价。佣金另计，仍满足全篮子的现金及缓冲要求。

必须同时处理以下边界，不能只在最终结果上多写一行裁剪：

1. 单股端点和单股对数凹整数搜索，把上端点限制为费用预算与50%数量上限的较小值。无法购买1股的证券报告“cap下不可行”，不假称已经评估所有原域状态。
2. 每个可行股票数量k的初始种子、按发行人唯一的support种子、加减股及转移邻域，都生成cap内可行数量。否则大量越界proposal被忽略可能造成预算耗尽语义错误或不必要的遍历。
3. 32步连续候选需要同一cap约束下的可行顶点/取整；保留现金顶点、原步长及唯一发行人整理规则。不能给不可执行的整仓候选评分后只裁剪胜者。连续松弛和整数取整仍是启发式，不宣称全局最优。
4. 每次精确目标求值均记入原8192预算；32次连续步及其精确复算沿原口径单独报告。重复候选不重复计数，新增支路不得偷偷另跑一整次旧选择器。
5. 新方法用自己的方法ID、源哈希和结果字段；旧post-cap封装即使继续做防御性裁剪，也必须是恒等操作，不冒充原未受约束的raw selection。

当前训练目标上界来自更大的未限仓域，仍可作为约束域的宽松上界，但应如此标注。不能将该上界或搜索邻域耗尽说成已证明50%约束内全局最优。

## 同预算和训练分数的边界

数学上，真正的约束全局最优不会比一个可行的旧裁剪解更差；现有预算只允许有限启发式搜索，因此新版本不自动具备这个保证。如果要把旧裁剪解作为保底候选，必须将获得及评分它的计算计入相同预算，不能暗中增加一个8192次旧搜索。不同资金路径下也不能复用原基准旧金额的解来声称新分支保底。

可保持相同253日、12情景、固定50%、费用、整数股、同发行人唯一、8192/32及固定种子，不添加新的风险阈值。但“同预算”仅指上述明确计算口径，不等于新旧搜索遍历到完全相同的候选或耗时必然相同。

## 为什么它也可能更差

当前两窗平均现金约41%～42%。约束内排序可能把原来裁剪后留下的现金用于第二只强势股，使总股票敞口明显上升。单股更分散，不代表组合回撤更小；同一市场方向或行业的两只股票可能一起跌。更积极地拟合仅12个历史情景还可能增加过拟合。

其他风险包括换仓数量/成本增加、整数与费用导致不同资金规模下选股变化、连续候选变换后搜索覆盖变差，以及原历史候选池偏差仍然存在。训练分数更高、现金更少或多拿一只股票，都不能作为生产采用理由。

## 若主agent决定继续，唯一有限对照的边界

先完成数学反例与小域手工枚举核验：现金/费用守恒、q上限、同发行人、保留现金、cap下全部单股与可行k覆盖、边界价格超过半净值、精确tie-break、8192/32计数及基准零搜索重放。再由独立agent审查，固定新方法源和单一清单。

经济对照仅是“现行月度选择后裁剪+20%退出”对“约束内月度选择+20%退出”，不加A、不改退出、不改50%、不换训练长度。若获准运行，仍按两个原固定窗口共31个月度调用、各自真实分支净值、同执行成本与预算上限；仅一次，不扫参数。保持两窗收益不低、回撤不高的必要门槛。

预计开发和双agent前置核验约需1～2小时，正式31调用可参考本轮约15分钟的同类运行，但新的搜索路径可能更慢，必须使用外层硬超时。若当前时间内前置证据不充分，应只交付机制和准备结果，不借截止时间跳过核验或把更高训练分数当作完成策略优化。

## 后续诊断产生了更窄的优先方案

主agent的`scripts/audit_capped_training_frontier.py`已对原31个月保存的`best_by_k`逐个裁剪并重新计算训练分数，没有生成候选或执行新账本。早窗19个月没有更高分的已保存合规篮子；后窗只有2026-01-30和2026-03-31两个原资金路径锚点存在严格更高的裁剪后训练分数。因此应优先考虑只重排同一次搜索已经生成的篮子，暂不重写约束内优化器。

较窄候选可固定为：原8192+32搜索完成后，对其`best_by_k`逐股50%裁剪、去重并按相同精确情景财富乘积评分；原裁剪篮子必须包含在竞争中，只有严格更高分才替换，同分保持现行篮子。多个严格胜者之间使用原低名义额/字典序规则。额外裁剪评分次数单独记录，不能因为没有新增候选生成就声称没有新增计算。它只是在原无约束搜索每个k的保存赢家之间重排，仍不是cap约束域完整搜索。

如果获准，可先逐步执行验证早窗19个月完全等价、零新搜索。后窗从2025-07-31至2026-01-30共7个月，只有当整份实际账户、价格、搜索参数及来源绑定与原保存调用完全相同，才复用该月原始搜索结果再重排。1/30首次改变目标后，2026-02-27起余下5个月必须基于新分支实际净值重新调用原选择器；尤其不能拿原路径3/31旧篮子作为新分支决策。

新版本需独立decider、沿原20%退出的隔离包装器，以及不调用候选实现的重排序核验；不叠加已拒绝的A。预计准备和审查约30～60分钟，余下5次新调用可参考2～3分钟，但必须登记硬限时。当前该较窄方案仍处于可行性阶段，尚未实现或运行。
