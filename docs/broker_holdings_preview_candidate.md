# 已有持仓的资金预览：候选接口

状态：2026-11-14 01:47 已部署本阶段预览功能。前端首次转入预览已接入“现有持仓全部在汇丰”显式确认，默认不选；账户版本变化后清除确认。已有盈立持仓时不适用这个简化入口。

`POST /api/strategy-roa/funding-preview` 可选接受 `broker_holdings`，包含 `account_revision` 和 `positions`。每行必须提供 `broker`（HSBC 或 USMART）、`security_id`、正整数 `quantity`。版本必须匹配当前账户，两家持仓合计必须与正式账户逐证券相等，同券商同证券不得重复。

该输入只用于本次只读预览，不持久化、不转移股票、不写现金。没有归属资料时仍明确等待核对，不从现金余额推断股票归属。

本候选放行已有持仓下的新增买入预算，卖出按确认归属分配（同证券两处持仓时先分配汇丰）。重复卖出不得超过剩余持仓；未成交卖款不参与买入预算。卖出费用未含在买入费用预算中。存在挂单仍不支持。当前仍只支持汇丰免费额度已用尽的情形，不能宣称完整双券商分配已经上线。

验证：11 项预算预览测试、6 项 HTTP 测试通过。HTTP 编排测试模拟建议校验结果，不能替代真实行情、页面或转账到账验收。

前端 DOM 测试覆盖未确认时不发请求、提交真实股数与版本、版本变化清除确认。完整启动校验和正式页面入口、现金未确认拦截已通过；账户前后完全一致。尚未验收真实转账及完整分配结果，不代表双券商闭环完成。

## 转账记账边界

三项隔离场景测试验证：两边均到账且合计不变时不会产生外部入金；明确确认的转账费用不会计为外部本金；在途扣款及后续到账仍分别保留未分类差额，不会自动当作出金和入金。

发现的真实缺口：现有合并账本没有在途资产和两端转账配对。如果转出时只填已结算购买力、到账后再填余额，会产生一负一正两笔未解释差额。不能靠把它们标为出金/入金来假装解决，也不能把在途金额加进可买入现金。

下一步应实现带唯一转账编号的两端记录，分离可交易现金与在途资产，到账核对后配对冲销；转账费用单列。发生期间的其他成交、外部入出金不得混入配对。正式上线前用同日到账、跨日到账、重复录入、金额不符四类场景验证账户总资产和外部现金流。当前不要求用户进行转账来测试。

`core/broker_internal_transfers.py` 已实现隔离的纯事件计算候选：唯一转账编号、转出本金与已确认费用、分批到账、重试幂等、版本冲突及超额到账拒绝。5 项场景测试通过。尚无持久化/API/UI，也未接入正式净资产计算；不能据此宣称在途资金功能已上线。费用仅支持转出时明确提供的费用，后续扣费与退款需另行设计，不能自动补差。
