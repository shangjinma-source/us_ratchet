# 月度快照读取优化

月度数据采用后，工作台读取目标时需要重新验证已保存的来源。旧读取器对每个小文件请求最多 32 MiB 的缓冲区；大量重复读取使目标接口变慢。

R47 使用独立的 sized reader：先检查已打开文件的实际大小，再读取实际大小加一个字节。仍检查原有路径、大小上限和 SHA256，并拒绝读取期间发生变化的文件。没有缓存验证结果，也没有放宽报价时效、来源完整性或月度采用条件。

原封存模块保持不变，新模块通过 V27 配置的源码哈希清单接入。月度 activation 继续继承原采用和锁定逻辑；原升级交接包装器以及账户、目标、历史归档约束仍然执行。交易规则没有改变。

验证包括十项读取边界及原新行为对照测试、真实已采用快照的精确等价检查，以及真实月度路由接线检查。后两项本地测得约 7.7 秒和 15.4 秒；这些是独立调用耗时，不是线上端到端耗时，也不构成严格的旧新 A/B 性能比较。

上线必须另行核验活动配置及全部源码哈希、真实 HTTP 返回，以及账户、目标和已采用月度数据前后不变。只读检查不能证明现金保存、新月目标创建或真实成交承接通过；这些需要对应的真实用户事件。

后续公告解析优化将同一份 RSS 的解析与文本规范化移至一次区间校验的开始，各证券仍分别匹配并保留完整原审计行。没有跨请求缓存。真实 98 只证券的全部匹配与阻断结果相等，局部耗时约 2.43 → 0.84 秒；完整已保存月度收据校验结果亦相等，约 7.42 → 5.59 秒。上述为本地单次对照，不能代表并发页面的整体提速。

页面读到旧月目标时先提示用户核对现金并生成本月目标，省去必然被月份检查拒绝的建议请求。只有用户正常提交现金才走原新月生成流程；自动刷新不会生成目标。
